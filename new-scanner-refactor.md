# New Scanner Refactor Plan

The goal is to make Film-Juicer’s scanner path numerically identical to **agx-emulsion** while removing all legacy behaviour. The steps below are intentionally self-contained so each can be verified independently. New identifiers mirror the Python names (camelCase → PascalCase/C++ snake case where appropriate) to make A/B reviews trivial.

## Context
- `scanner-refactor.md` assumed its plan was finished, yet all code was reverted, leaving Film-Juicer on the legacy scanner implementation.
- The previous refactor attempt produced heavy underexposure and desaturation when `PrintBypass=false`, showing that the plan did not control density normalization, illuminant parity, or scanner gain.
- `viewing-illuminant-refactor.md` already highlights the SPD single-sourcing requirement; the new plan must integrate that work and extend it so the scanner path matches **agx-emulsion** numerically across both the negative and print media.
- Every step below is self-contained, lists its acceptance evidence, and calls out failure modes so we can avoid repeating the exposure/saturation regressions.

## Scope & invariants
- Geometry is single-sourced: the existing `CameraFilmFormatMm` UI control remains the **only** film-format input. There is no scanner-specific film-format knob. Film-Juicer always renders the full image and does **not** implement agx-emulsion’s preview resize path; this is equivalent to running `AgXPhoto.process` with `full_image=True` and `preview_resize_factor=1.0`. All µm→px conversions use `pixelSizeUm = CameraFilmFormatMm * 1000 / max(frameWidthPx, frameHeightPx)`, where `frameWidthPx`/`frameHeightPx` are the full clip bounds after the host’s renderScale. Scanner optics sliders (`ScannerLensBlurSigmaPx`, `ScannerUnsharpMask`) are already in pixel space and never convert µm, and the scanner path never applies additional crops, resizes, or offsets beyond what the host provides.
- This refactor is CPU-only and parity-first. GPU kernels, device uploads, and any backend/pool abstractions are out of scope here and will land in a separate follow-up once CPU parity is locked.
- All scanner spectra stay on the canonical 380–780 nm @ 5 nm axis. Every ingest/resample (`json_wavelengths_match_reference_axis()`, `install_standard_illuminant()`, `resample_pairs_*`) must prove the axis matches and hard-fail on mismatches; no alternate axes or per-backend resampling tweaks are allowed.
- Data layout stays GPU-friendly but CPU-owned: planar CMY SoA buffers with consistent stride/origin and 32-byte alignment. That layout is fixed for this refactor so the later GPU branch can reuse it without changing CPU code.
- **Progress:** Steps 1–5 completed (UI/hash/profile ingestion through CPU-only SoA staging with active colour). Step 6 is next.
  - **Current:** Steps 1–6 are implemented in code (UI/hash/profile ingestion; per-medium illuminants/tables/ranges/caches; SoA staging + print bridge; scanner optics TU with LUT/blur/unsharp/glare; CPU-only enforcement with legacy AoS scanner removed; generated colour space tables with cached per-medium colour runtimes). GPU paths are fatal. Color runtime now adapts from the scanner illuminant white directly into the chosen output space using the generated XYZ→RGB matrices and cached encoding flags.

### Step 1 – Align the scanner parameter surface and profile ingestion
_Status: completed (hash helpers added; scanner optics/LUT UI threaded; profile grain and glare ingested with per-build print glare removal)._
- **Implementation notes**
  - Ship this step as at least two changes: (1) host/UI cleanup + `Scanner::Options` threading (delete legacy params, add `ScannerLensBlurSigmaPx`/`ScannerUnsharpMask`, plumb the struct); (2) profile ingestion + WorkingState mutations (grip JSON glare/grain data, add the structs, enforce the immutable→clone→optional removal flow). Optionally land the WorkingState mutations as a third change if the JSON ingestion diff gets large. Keeping these concerns separate mirrors the UI vs. profile vs. state modules and makes parity validation simpler per merge.
  - **Tasks**
  - **Cache keys (canonical; used everywhere)**
    - Hash helpers: `hash_float_span(const float*, size_t)` uses 64-bit FNV-1a (offset `0xcbf29ce484222325`, prime `0x100000001b3`), canonicalizes `±0.0f` → `0.0f`, and **fails** on any non-finite sample (log a fatal `JTRACE` before hashing). Callers must sanitize inputs to match agx-emulsion semantics (e.g., `nan_to_num` for sensitivities, `nanmax` for ranges) before hashing. `hash_bytes(const void*, size_t)` is the companion for trivially copyable types. All keys must combine non-float fields via `hash_bytes` in field order and float slices via `hash_float_span`; no ad-hoc hashes are permitted.
    - Data digests (sanitized, finite only): `ScannerIlluminant.hash = hash_float_span(SPD samples + normalization scalar)` after validating the SPD is finite; `Spectral::SpectralTables.tablesHash` seeds from `ScannerIlluminant.hash`, then hashes the reference axis and CMY tables via the helpers; `ScannerDensityRange.digest` hashes the per-channel fog and maxima (for example, `min_cmy` then `max_cmy` in CMY order) after range capture has produced finite values for every required channel. On validation failure for any digest input, mark caches invalid and abort the render instead of reusing prior LUTs/optics.
    - Define two keys (with `ScannerMedium` fixed as `Negative=0, Print=1`):
      - `ScannerStaticKey { ScannerMedium medium; uint64_t tablesHash; uint64_t densityRangeHash; uint64_t glareHash; uint64_t colorRuntimeHash; uint32_t lutResolution; }` with `hash = hash_bytes(fields in declaration order)`. This feeds LUT/spectral caches and never includes geometry. Until Step 6 produces real colour matrices, set `colorRuntimeHash` to a fixed identity digest so later colour work invalidates caches automatically.
      - `ScannerRuntimeKey { uint64_t settingsHash; uint32_t frameBoundsVersion; }` with `settingsHash` built from `hash_bytes(useLut)` followed by `hash_float_span(lensBlurSigmaPx, unsharpSigmaPx, unsharpAmount)` (requires finite inputs, still canonicalizes `±0.0f`) and `frameBoundsVersion` hashed via `hash_bytes`.
    - `ScannerKey { ScannerStaticKey staticKey; ScannerRuntimeKey runtimeKey; uint64_t hash; }` with `hash = hash_bytes(staticKey.hash, runtimeKey.hash)`. Optics/glare caches use this combined key.
    - `SpectralLutBuffer.hash = hash_bytes(ScannerStaticKey.hash)` immediately after `_spectral_lut_compute`; LUT caches ignore geometry and runtime-only fields.
  - Delete the Film-Juicer-only scanner controls (`ScannerEnabled`, `ScannerAutoExposure`, `ScannerTargetY`, `ScannerFilmLongEdgeMm`) and replace them with the four values required for agx parity: `ScannerLensBlurSigmaPx`, `ScannerUnsharpMask`, `ScannerUseLUT`, and `ScannerLutResolution`. The first two mirror `params.scanner.lens_blur`/`unsharp_mask`, and the latter pair explicitly governs `_spectral_lut_compute` so a future GPU path can reuse the same switchboard while the current refactor stays CPU-only. All four controls ship together so Resolve presents a stable surface from the first refactor drop. Blur/unsharp sliders feed `Scanner::Options`, and the LUT toggles live inside `Scanner::Settings`, keeping struct ownership fixed before we start moving optics code. No migration path for old presets is required, the new IDs replace the legacy ones outright, and the scanner is always active just like agx (hosts that want a pass-through simply bypass the plug-in). Keep a thin compatibility shim that maps the always-on scanner/options to the existing `Scanner::Params` entry points until Stage 3/4 delete the legacy scanner path; the UI does not expose the old toggles.
  - **Single geometry source**: Keep the existing `CameraFilmFormatMm` param; remove any scanner film-format field from params/structs/caches. All µm→px math (DIR, halation, grain microstructure, glare blur) uses a shared `pixelSizeUm` computed once per render from `CameraFilmFormatMm` and the full clip bounds after the host’s renderScale: `pixelSizeUm = CameraFilmFormatMm * 1000 / max(frameWidthPx, frameHeightPx)`. The scanner refactor does **not** introduce any new geometry knobs: scanner optics remain strictly pixel-space, and no scanner parameter carries a µm unit. Any future geometry changes (crop behaviour, auto-exposure mask, micrometre-per-pixel formula) must be made in the shared camera geometry helper and validated against `agx-documentation.md`.
  - **Scanner parameter reference**
    - `ScannerLensBlurSigmaPx`: `Scanner::Options`, OFX `Double` (`kOfxParamDoubleTypePlain`), hard range `[0.0, 10.0]`, display range `[0.0, 3.0]`, default `0.55`, grouped under “Scanner Optics”.
    - `ScannerUnsharpMask` (`sigma_px`, `amount`): `Scanner::Options`, OFX `Double2D`, sigma range `[0.0, 5.0]`, amount range `[0.0, 3.0]`, default `(0.7, 1.0)`, also inside “Scanner Optics”.
    - `ScannerUseLUT`: `Scanner::Settings`, OFX `Boolean`, default **enabled**, located in the “Scanner Math” expert group.
    - `ScannerLutResolution`: `Scanner::Settings`, OFX `Integer`, range `[17, 128]`, default `17`, hosted alongside `ScannerUseLUT` within “Scanner Math”.
  - Extend `ProfileJSONLoader` with the exact profile-backed slices consumed by agx during scanning: `negative.grain.active`, `negative.grain.density_min`, and the full `glare` objects for both `negative` (active/percent/roughness/blur) and `print_paper` (active/percent/roughness/blur plus `compensation_removal_{factor,density,transition}`). Treat the existing root-level `grain`/`glare` blocks in film profiles as the negative entries and the root-level `glare` in paper profiles as the print entry. Require every listed field to exist and be finite; missing objects or fields are fatal (log which field) rather than defaulting. Ingest `density_min` in CMY order, store verbatim, and only remap to legacy RGB-layer helpers at the few remaining sites that still expect `densB/densG/densR`. When `compensation_removal_factor > 0`, mutate the cloned print density curves during working-state rebuild exactly the way `remove_viewing_glare_comp()` does (mirroring agx’s `_apply_profiles_changes`) before any render work begins so the scanner never sees compensated data; if the factor is zero, leave the clone untouched but still cache the immutable JSON curves. The mutation happens in `WorkingState` (per-build) rather than `BaseState`, and `Print::load_profile_from_dir()` keeps returning the immutable JSON snapshot while each working-state clone decides whether to strip compensation. Step 2’s density-range capture points at this cloned, post-removal buffer so there is a single mutation site (`JSON → Print::Profile (immutable) → WorkingState copy → optional removal`) identical to agx’s ordering.
  - Introduce typed structs that mirror agx’s DotMaps instead of the grab-bag `Scanner::Params`: e.g. `Scanner::Options { float lensBlurSigmaPx; float unsharpSigmaPx; float unsharpAmount; }` (defined in `Scanner.h` next to the optics code) plus `ProfileGlare`/`GrainMetadata` structs carried by `BaseState`/`WorkingState`. `GrainMetadata` only needs the fields required for scanner normalization today (`active`, `density_min` in CMY), but keep the struct in shared state so future grain refactors can append fields without ABI churn. Print glare metadata should live alongside the rest of the paper profile (`Print::Profile`/`Print::Runtime`) so working-state rebuilds can copy both mediums’ glare structs wholesale. Populate the scanner struct exclusively from the runtime parameter block—no more host toggles—and rely on code review/parity docs instead of `static_assert` size guards to keep the surface in sync with agx (the struct is simple enough that assertions add little value).
  - Thread the new structs through `JuicerEffect` → `JuicerProcessor` → scanner runtime using the same field names as agx JSON (`lens_blur`, `unsharp_mask`). `JuicerEffect` fetches the new OFX params, `ParamSnapshot` stores them (but keeps them out of `hash_params()` to avoid rebuild churn), and `JuicerProcessor` hands a `Scanner::Options` to the optics module every render. Wire `WorkingState` rebuilds so the film and print paths pull glare/grain data from the profile objects instead of the host. When print glare removal fires inside the working-state build, reuse the existing `remove_glare_compensation_from_curves()` helper (it already mirrors agx’s `remove_viewing_glare_comp()` math) instead of re-porting it; keep the raw JSON curves intact in `InstanceState` so every build starts from the same baseline while paying the per-build copy cost only when the compensation parameters are active. This mirrors agx’s `_apply_profiles_changes()` lifecycle (immutable profile -> per-render clone -> optional curve mutation), avoids double-removing glare if multiple working states exist simultaneously, and makes it trivial to prove the scanner path always starts from the same on-disk data. The trade-off is a small per-build memcpy/filter cost, but we avoid the more serious drift that would happen if `InstanceState` mutated its cached curves in-place.
  - Keep the promoted JSON density curves (`DoublePairs`) cached in `InstanceState` alongside the immutable `Print::Runtime` snapshot, and only run `remove_glare_compensation_from_curves()` during a `WorkingState` rebuild when the profile’s compensation-removal parameters are non-zero before we linearize the curves into `Spectral::Curve`s. This exactly matches agx’s “clone → mutate → discard” model, guarantees every rebuild starts from the same on-disk data, and keeps glare stripping out of the profile loader. The downside is a modest per-build memcpy, but that cost only appears when parameters change and the profile actually requests compensation removal, which avoids doing extra work (and touching floating-point samples) when compensation is disabled.
  - Treat `negative.grain` and both `glare` blocks as required JSON schema. The shipping `_uc`/`_auc` assets we rely on already ship this metadata (parity with agx-emulsion), so `ProfileJSONLoader` should log a fatal `JTRACE` and abort when those objects are missing or contain non-finite samples instead of synthesizing defaults. This keeps Film-Juicer aligned with the Python reference and surfaces broken custom assets immediately; the trade-off is that legacy community profiles without the metadata will now fail to load, but that is the same contract agx enforces.
  - Store `ProfileGlare`/`GrainMetadata` inside `Profiles::AgxFilmProfile` → `BaseState`, clone them into every `WorkingState`, and keep the print-paper copy inside `Print::Profile`/`Print::Runtime` so the render thread only touches immutable snapshots. The struct layout should mirror agx’s DotMaps (CMY ordering, booleans, compensation fields) so future grain/glare work can drop directly into place; the cost is a bit more plumbing through the loader and rebuild path, but it eliminates ambiguity about ownership.
- **Implementation notes**
  - *Scanner slider churn*: The new `ScannerLensBlurSigmaPx` and `ScannerUnsharpMask` controls only influence runtime convolution, so they should *not* contribute to `ParamSnapshot::hash_params()` or trigger full `WorkingState` rebuilds. Fetch them in `JuicerEffect`, thread them through `JuicerProcessor`, and let the processor rebuild its blur kernels when the values change. That keeps renders responsive, avoids unnecessary rebuilds, and matches agx where `params.scanner` is a per-render DotMap instead of a profile-level knob. The trade-off is that any future scanner logic that *does* rely on rebuilt spectral data must hook into a separate dirty bit, but today’s optics-only sliders don’t warrant the rebuild penalty.
  - *Print glare removal site*: Glare compensation should be stripped inside `rebuild_working_state()` so concurrent working states never double-apply the removal. The helper already lives in `Print.cpp`, so the only work is to retain the JSON curves long enough for the rebuild to call it. Pros: mirrors agx’s `_apply_profiles_changes()`, guarantees per-build determinism. Cons: adds an extra copy step, but the copy happens off the render thread and only on parameter changes.
  - *Ownership & mutation contract*: The data flow must remain `JSON on disk → ProfileJSONLoader → BaseState/Print::Profile (immutable snapshots) → WorkingState clone → optional glare-compensation removal → density-range derivation (Step 2) → render-time read-only access`. Neither `ProfileJSONLoader` nor `Print::Profile`/`Print::Runtime` may mutate the promoted curves after ingest; all compensation runs once per working-state rebuild using the freshly cloned buffers so scanner metadata always reflects the post-removal data.
- **Risks & Mitigation**
  - *Risk*: Leaving any of the legacy scanner toggles in place lets downstream code double-apply exposure or geometry fixes.  
    *Mitigation*: Remove the parameters outright and gate all scanner runtime construction behind the new struct; parity docs/code review keep the struct surface in sync with agx since the field list is tiny and easy to audit.
  - *Risk*: Profiles without glare metadata would leave the scanner path without `profile.glare.*`, causing crashes or mismatched brightness.  
    *Mitigation*: Do exactly what agx does—treat the profile as invalid. If `glare` is missing (e.g. the `_oc` research variants), abort the ingest and surface a `JTRACE` pointing back to the JSON so the asset gets fixed instead of silently fabricating defaults.

### Step 2 – Rebuild `WorkingState` scanner metadata per medium (negative & print)
_Status: completed (viewing illuminants pinned to agx axis with hashes/normalization; per-medium tables, density ranges, glare hashes, and static keys built during WorkingState rebuild)._
- **Implementation notes**
  - Phase this work across at least three deltas: (1) viewing-illuminant cleanup + `ScannerIlluminant` struct (delete the UI override, enforce profile names, reuse the Step 1 hash helpers); (2) spectral-table/cache integration (extend `Spectral::SpectralTables` with `illuminantHash`, add accessors, make the legacy scanner path consume the new structs); (3) density-range capture + per-medium validity flags (post-glare-removal measurement, flag plumbing, fatal error surfaces). Each chunk stands on its own and keeps regressions localized.
- **Tasks**
	  - Build `ScannerIlluminant` records directly from each medium’s `profile.info.viewing_illuminant`, using the same `np.sum(SPD * ȳ)` scalar agx computes before dividing XYZ. Treat missing or invalid viewing names as fatal profile errors: log a `JTRACE` and abort the working-state rebuild/render instead of falling back to D50 so parity renders fail fast just like `_density_cmy_to_rgb`. Every ingest path must call `json_wavelengths_match_reference_axis()` / `install_standard_illuminant()` to prove the 81-sample SPD matches the immutable agx axis; mismatches hard-fail the rebuild and there are no alternate axes. `ScannerIlluminant` now stores the pinned `Spectral::Curve`, `float normalization` (`∑SPD·ȳ`), `float whiteXYZ[3]`, `float whiteXY[2]`, and a `uint64_t hash`. Use the Step 1 hash helpers (`hash_float_span`/`hash_bytes`) for **all** scanner hashes—illuminants, density ranges, static/runtime key components, LUT caches, glare caches, and RNG seeds—after validating the underlying floats are finite. Only recompute the hash when the underlying samples change so cached keys stay stable. All SPD names resolve to the CSV assets in `Resources/illuminants/`, so no fallback logic is required once the profile key is validated.
  - Fold in the viewing-illuminant refactor completely: delete the legacy UI overrides (the `ViewingIlluminant` choice parameter, `InstanceState::filmViewingIlluminant`, and any downstream checks) so every scanner or print consumer only reads `WorkingState::negativeScannerIlluminant`/`printScannerIlluminant`.
  - Cache the full scanner illuminant curve (`Spectral::Curve`), its hashed key, `XYZ_white`, chromaticity, and the normalization scalar so LUT builders and adaptation matrices can detect when to rebuild. Extend `Spectral::SpectralTables` with `illuminantHash` (copied from `ScannerIlluminant.hash`) and `tablesHash` computed from `{illuminantHash, lambda axis, deltaLambda, invYn, whiteXYZ, refIllumWhiteXYZ, Ax/Ay/Az, Xbar/Ybar/Zbar, epsC/epsM/epsY, baseMin/baseMid, hasBaseline, baselineMixReference}` using the Step 1 hash helpers. Glare randomness should continue to follow the profile’s `glare` parameters exactly as in agx. Expose accessors so the legacy negative-only scanner path can consume the same data immediately, then delete that compatibility layer once Step 3 wires in the new entry point.
	  - Compute `ScannerDensityRange` structs for both media as a direct port of agx’s per-channel formulas. For the negative medium, set `range.min_cmy` from `negative.grain.density_min` (CMY order), then compute `range.max_cmy = np.nanmax(negative.density_curves, axis=0) + range.min_cmy`. For the print medium, set `range.min_cmy = 0` (all channels) and `range.max_cmy = np.nanmax(print.data.density_curves, axis=0)` (`_normalize_print_density` never adds a baseline). `np.nanmax` must ignore isolated NaNs exactly like agx. After these maxima are known, precompute `range.inv_max_cmy = 1.0f / range.max_cmy` for all finite channels; treat “no finite per-channel max” (all-NaN/inf, missing curves, or missing `density_min` on the negative path) as fatal with a `JTRACE` for the affected medium. Perform this measurement inside `rebuild_working_state()` immediately after the cloned `Print::Profile` curves have (optionally) run `remove_glare_compensation_from_curves()`, then stash the CMY `min/max/invMax` vectors inside a scanner-specific metadata block that lives next to the working-state copy. `InstanceState` / `BaseState` only cache the immutable JSON curves, their promoted `DoublePairs`, and the profile flags; the “golden” ranges we hand to `_normalize_{film,print}_density` must always come from the post-removal clone so Step 1 and Step 2 share the same mutation order (JSON → Profile → WorkingState copy → optional removal → range capture). On every rebuild, recompute the CMY `min/max` once and always install them, refreshing `ScannerDensityRange.digest` (feeds `ScannerStaticKey.densityRangeHash`). Hash only after this validation; do not hash all-NaN data. `ScannerDensityRange` is a trivially copyable struct storing `float min_cmy[3]; float max_cmy[3]; float inv_max_cmy[3]; uint64_t digest;` in CMY order so it maps cleanly to future GPU constant buffers.
  - Store explicit per-medium booleans (`negativeScannerValid`, `printScannerValid`, `printGlareCompensated`, etc.) indicating whether glare data, illuminants, density ranges, and the one-time print glare-compensation removal step succeeded; any missing data should block rendering with a clear error and a `JTRACE` **for the medium being scanned**. When `PrintBypass=true` (agx’s `compute_negative` path) the engine only requires the negative metadata, so print failures are surfaced but do not prevent the bypass render; conversely, print-mode renders refuse to start unless the print runtime is fully valid.
	- **Risks & Mitigation**
	  - *Hash churn vs. build counter*: `ScannerStaticKey` (data-only) and `ScannerRuntimeKey` (settings + geometry) carry all invalidation; `WorkingState::buildCounter` still seeds RNG/logging but should not force LUT rebuilds when hashes are unchanged. Hashes are only emitted from validated, finite data; validation failures abort the render and mark caches invalid rather than reusing stale LUTs/optics.
	  - *Risk*: Using mismatched illuminants recreates the desaturation bug.  
	    *Mitigation*: Assert during working-state rebuild that both scanner tables consume the same SPD hash used for adaptation, and abort the render if a mismatch is detected.
	  - *Risk*: Density ranges drifting from agx cause exposure shifts or hide missing data.  
	    *Mitigation*: Mirror the exact `_normalize_film_density` / `_normalize_print_density` formulas, abort when any channel lacks a finite max (all-NaN/inf or missing inputs), always refresh the stored range/hash on rebuild, and only emit a warning when deltas exceed the diagnostic epsilon so parity changes propagate instead of being suppressed.

### Step 3 – Introduce a shared density staging layer (the missing bridge)
_Status: completed (single SoA slab with negative fill, in-place print bridge, scanner handoff consumes staged densities with ROI disabled)._
**Plan of attack (ship as incremental milestones)**
  1. **Stage 1 slab + negative density writer**: introduce a single lightweight `DensityBuffer` wrapper (CMY SoA: three `std::vector<float>` planes in C/M/Y order, row-major, width-sized stride) with `originX`, `originY`, `width`, `height`, and `stride` metadata. Port the existing RGB→density logic (scalar + spatial DIR) into a full-frame pass that fills this slab for the current bounds; legacy print/scanner paths keep using temporary AoS triples until the handoff lands.
  2. **In-place print conversion**: split `run_print_pipeline_from_dir_corrected_densities` into `negative_density_to_print_raw()` + `print_raw_to_density()`, run the enlarger pipeline as a second full-frame pass that reads negative CMY from the slab and overwrites it with print CMY when `PrintBypass=false`. When bypassed, Stage 2 is skipped and the slab stays negative.
  3. **Scanner handoff & optics entry**: alias the `DensityBuffer` wrapper as `ScannerDensityBuffer`, thread it plus `Scanner::Options` into Step 4’s `ScannerOptics::render_density_to_rgb()` entry point, and delete the legacy “RGB→density inside scanner” branch so Stage 3 exclusively consumes the active slab (negative when bypassed, print otherwise). Once this is stable, Step 4 can move scanner optics into their dedicated TU. GPU kernels and uploads remain out of scope for this refactor.
**Tasks**
  - **Geometry / pixel size (single source)**: Derive `pixelSizeUm` once per render as `pixelSizeUm = CameraFilmFormatMm * 1000 / max(frameWidthPx, frameHeightPx)`, where `frameWidthPx`/`frameHeightPx` are the full clip bounds after the host’s renderScale. Film-Juicer does not perform agx’s preview downscale or `_rescale_to_original`; it is equivalent to `full_image=True` and `preview_resize_factor=1.0`, so no additional in-plugin resampling is applied. The clip bounds (full frame) are the only geometry used; renders must run over the full frame, not ROIs/tiles. Advertise this up front by setting `setSupportsTiles(false)` on the effect and both clips so hosts never tile; keep the render-time fatal guard as a last resort. Feed `pixelSizeUm` into all µm-based kernels (DIR diffusion, halation, grain microstructure, glare blur). Scanner optics remain pixel-space only; no scanner parameter carries a film-format or µm unit, and the scanner path never scales or crops images on its own.
  - Split the renderer into: (1) RGB → negative densities with DIR + grain; (2) optional print simulation producing print densities in-place; (3) scanner consumption. Every render processes the full clip bounds in one pass; ROIs/tiles are not supported. Halos derived from the kernels still size scratch buffers but do not relax the full-frame requirement.
  - Each `JuicerProcessor` owns one `DensityBuffer` slab plus a `StageScratch` struct wrapping the read-only DIR/print/glare/grain kernels/taps (`Tneg`, `Ee_*`, `Tpreflash`, `Tprint`, `Ee_viewed`, DIR kernels/buffers, glare taps) and a `std::vector<PrintBridgeScratch> scratchPerWorker` sized to the task-set worker count. At render start, ensure capacity for the current full-frame bounds (`width * height`); if bounds shrink, shrink the slab to fit. Stage 1 always fills the slab as negative for the current full frame. Stage 2, when `PrintBypass=false`, reuses the same slab and overwrites it with print densities. Overlapping ROIs are never merged because ROIs are not legal.
    - Stage 1 runs over the full frame (reuse the current multithread/task-set path) to populate the negative slabs. Split the current `buildSpatialDIRCorrectedDensities` into helpers that take explicit plane views, reuse the existing DIR kernels/grain code, and accumulate the density per plane. Log exposure planes feed the SoA writer directly so RGB→logE runs exactly once per pixel per frame. Map sampled densities into CMY order as written (C/M/Y = B/G/R if sampling stays RGB-ordered). `JuicerEffect::render` fetches the full bounds via `Clip::fetchImage(time, clipBounds)` and still early-outs via `copyNonFloatRect` for integer clips so the float-only path mirrors agx.
    - Preserve the current non-float handling path: `JuicerEffect::render` continues to early-out via `JuicerProc::copyNonFloatRect` when the host provides 8/16-bit buffers, and Stage 3 simply copies the source alpha channel after optics/encoding. This keeps the staged pipeline float-only (parity with agx) while retaining today’s “passthrough for unsupported depths” contract. Alpha is otherwise ignored in Stage 1/2 and copied (or set to 1.0) in Stage 3.
    - Stage 2 runs only when `PrintBypass=false`. It iterates across the full negative slab, applies enlarger math + mid-gray compensation + preflash to produce print CMY (`AgXPhoto._film_density_cmy_to_print_log_raw` + `_develop_print`), and overwrites the slab with those print densities. Print bypass skips Stage 2 and keeps `ScannerMedium::Negative`.
    - Stage 3 consumes the single active slab (negative when bypassed, print otherwise) together with its metadata (`ScannerDensityRange`, glare params, illuminant hashes) and performs the scanner optics pipeline without recalculating densities. Because the slab covers the whole frame, Stage 3 emits RGB in a single pass, mirroring `_density_cmy_to_rgb`.
    - Implement `_normalize_film_density` / `_normalize_print_density` helpers as algebraic ports of agx (`process.py:301-312, 378-385`) using only the cached `ScannerDensityRange`. For the negative medium, `density_cmy_n = (density_cmy + range.min_cmy) * range.inv_max_cmy` and `density_cmy = density_cmy_n / range.inv_max_cmy - range.min_cmy`. For the print medium, `density_cmy_n = density_cmy * range.inv_max_cmy` and `density_cmy = density_cmy_n / range.inv_max_cmy`. Normalized CMY values are computed on the fly from the stored raw density and cached range whenever LUTs, optics, or debug exports request them, keeping only one SoA copy in memory. `_denormalize_*` mirrors these formulas inside the LUT callback so the spectral integration sees the same fogged densities as agx. A `ScannerMedium` enum must ride alongside each tensor to prevent mixing negative and print ranges.

If allocation fails, log a fatal `JTRACE` and abort the render. Concurrent renders allocate their own slab because contexts never share memory. No global pool, mutex, or custom deleter is required, which keeps debugging and crash dumps straightforward.

RNG seeding stays on the existing per-processor helpers for now (derive base seeds from `{frameBoundsVersion, frameTimeBits, workingState.buildCounter}`); richer RNG multiplexing belongs to the later GPU branch. The remaining steps keep this three-tier split intact.

### Step 4 – Rebuild the scanner optics module as a dedicated translation unit
**Implementation notes**

This sequencing keeps regressions isolated and parity checks focused per change.
**Tasks**

Whenever the rectangle changes, write the new rectangle to `InstanceState` and bump `frameBoundsVersion`. No alternate invalidation flags exist; `frameBoundsVersion` remains the sole geometry key (replacing the old `clipSerial`). The runtime holds only CPU data in this refactor; any attempt to dispatch a device/GPU path is a fatal error.
  - Reimplement `_spectral_lut_compute`, `_density_cmy_to_rgb`, and glare math line-for-line from agx-emulsion, honoring per-medium `ScannerDensityRange`, illuminants, and the denormalize → spectral-eval flow (`_denormalize_*` happens inside the LUT callback). Store LUT entries as `log10(XYZ + 1e-10)` just like `compute_with_lut`. Each `ScannerOptics::Runtime` owns a `SpectralLutBuffer { std::vector<float> cpu; uint64_t hash; uint32_t res; bool valid; }` where `hash = hash_bytes(ScannerStaticKey.hash)` immediately after `_spectral_lut_compute`. Wire the `ScannerUseLUT` checkbox (default **enabled**) and `ScannerLutResolution` slider (17–128, default 17) from `Scanner::Settings` into the optics runtime so `_spectral_lut_compute` follows the same “Scanner Math” UI group contract introduced in Step 1. `JuicerProcessor` hashes the settings once per frame (per the struct above) to decide whether the optics runtime must rebuild. When `ScannerUseLUT=false`, skip LUT allocation/build and call the direct spectral lambda per pixel; `settingsHash` still flips on toggle so caches remain coherent.
  - LUT rebuilds happen only when the LUT cache key (`ScannerStaticKey.hash`) changes or when a developer purges caches. The first render after a key change rebuilds the CPU LUT on the calling thread and caches it; subsequent frames reuse the cached CPU data until the static key changes again. `_spectral_lut_compute` failures (NaNs/infs from tables/range) log a fatal `JTRACE` and abort the render rather than falling back to direct eval. There are no async uploads or device fences in this refactor.
  - Feed the optics module with the raw density slab from Step 3. Each `ScannerDensityBuffer` records `originX/originY`, width, height, stride, and planar descriptors. Optics code iterates row-major over the slab, normalizes each sample on the fly for LUT lookup via `_normalize_{film,print}_density(density, range)`, and calls `_denormalize_{film,print}` inside the LUT callback using the same `ScannerDensityRange`. Raw planes remain available for debug exports, but no duplicated normalized copy exists. Because Stage 3 owns the SoA lifetime, the optics TU never recomputes RGB→density. Stage 3 pre-fills the destination OFX buffer (copy alpha from source or set 1.0) and hands a `PlaneView` describing those rows directly to `ScannerOptics::render_density_to_rgb()`, which writes RGB in place; blur/unsharp operate on that same buffer, so the optics TU never allocates a second image.
  - Apply lens blur and unsharp mask directly in pixel space after XYZ→RGB conversion but before output encoding, matching agx’s `apply_gaussian_blur`/`apply_unsharp_mask` ordering. Provide CPU kernels that operate on the row-major RGB buffer owned by Stage 3; keep the API surface simple enough that a future GPU backend can plug in alternative implementations without touching OFX glue. Unit tests confirm determinism by hashing a few coordinates and comparing the resulting samples across renders—we match agx’s statistical pattern (grain/glare distributions, blur, and fog) but not bitwise RNG parity.
