# New Scanner Refactor Plan

The goal is to make Film-Juicer’s scanner path numerically identical to **agx-emulsion** while removing all legacy behaviour. The steps below are intentionally self-contained so each can be verified independently. New identifiers mirror the Python names (camelCase → PascalCase/C++ snake case where appropriate) to make A/B reviews trivial.

## Context
- `scanner-refactor.md` assumed its plan was finished, yet all code was reverted, leaving Film-Juicer on the legacy scanner implementation.
- The previous refactor attempt produced heavy underexposure and desaturation when `PrintBypass=false`, showing that the plan did not control density normalization, illuminant parity, or scanner gain.
- `viewing-illuminant-refactor.md` already highlights the SPD single-sourcing requirement; the new plan must integrate that work and extend it so the scanner path matches **agx-emulsion** numerically across both the negative and print media.
- Every step below is self-contained, lists its acceptance evidence, and calls out failure modes so we can avoid repeating the exposure/saturation regressions.
- GPU acceleration is explicitly a follow-up. Steps 1–6 lock the CPU pipeline, parity fixtures, and optics TU before any `ScannerBackend`/pool abstractions or kernels are introduced in a separate branch once parity is proven.

### Step 1 – Align the scanner parameter surface and profile ingestion
- **Implementation notes**
  - Ship this step as at least two changes: (1) host/UI cleanup + `Scanner::Options` threading (delete legacy params, add `ScannerLensBlurSigmaPx`/`ScannerUnsharpMask`, plumb the struct); (2) profile ingestion + WorkingState mutations (grip JSON glare/grain data, add the structs, enforce the immutable→clone→optional removal flow). Step 2 owns the actual CMY range measurement, so Step 1 only introduces the `ScannerDensityRange` storage and keeps it zeroed until the later step populates it. Optionally land the WorkingState mutations as a third change if the JSON ingestion diff gets large. Keeping these concerns separate mirrors the UI vs. profile vs. state modules and makes parity validation simpler per merge.
- **Tasks**
  - **Hash ownership (authoritative digests)**
    - Treat `WorkingState::buildCounter` as the umbrella invalidation source, but keep it **out** of content hashes so spectral fingerprints remain stable across working states. Whenever a cache must be tied to a specific working state, combine `buildCounter` with the relevant content hashes via `hash_pack(buildCounter, …)` instead of folding it into the content digest itself.
    - Define `enum class ScannerMedium { Negative, Print };` in `Scanner.h` and store it beside every density tensor so cache keys never need to guess the active medium. `ScannerMediumRuntime` (added to `WorkingState`) becomes the authoritative container for `{ScannerMedium mediumTag; ScannerDensityRange range; ProfileGlare glare; ScannerIlluminant illuminant; const Spectral::SpectralTables* tables; const ColorRuntime* color; uint64_t mediumSpectralHash; uint64_t mediumOpticsHash;}`; the illuminant is stored **by value** so its `Spectral::Curve` and normalization survive working-state swaps without dangling pointers. `ScannerIlluminant` and `ColorRuntime` structs land in this step: place them in `Scanner.h` / `ColorTransforms.h`, initialize them with identity CAT02/XYZ matrices + D50 defaults, and keep them wired even though real values arrive in Step 2. Legacy code reads only `mediumTag` today while later steps fill the rest of the struct.
    - `ScannerMediumRuntime.mediumSpectralHash = hash_pack(mediumTag, hash_float_span(illuminant.samples), hash_float_span(SpectralTables.cmy), hash_float_span(densityRange.cmy))` and captures only the tables/curves that feed LUT math. To support this, `Spectral::SpectralTables` must expose immutable CMY spans (per-channel `const float*` + count in CMY order) and `ScannerDensityRange` must own its CMY min/max vectors in a contiguous `std::array<float,3>` so the helper can read canonical samples without copying.
    - `ScannerMediumRuntime.mediumOpticsHash = hash_pack(mediumSpectralHash, glareStructHash, ColorRuntime.hash)` so any glare or colour adaptation change propagates without forcing LUT rebuilds. `ColorRuntime.hash` folds `{outputSpace enum, inputIsOutputSpace flag, CAT02[9], XYZ→RGB[9], hash_float_span(illuminant.samples)}` to keep both CPU and GPU adaptation matrices deterministic. `glareStructHash` is the stable digest of the `ProfileGlare` struct (pack the bools as bytes, hash the float members through `hash_float_span()`), guaranteeing that any change to the profile’s glare metadata invalidates downstream caches even though the struct itself stays POD. It participates only in `mediumOpticsHash`.
    - Use `mediumSpectralHash` anywhere the code depends solely on the SPD/table inputs (LUT buffers, device spectral uploads, Stage 2 print bridges). Reserve `mediumOpticsHash` for glare kernels, colour-adaptation caches, and any RNG seeds that must rebuild when glare or CAT02 data changes; when a cache needs both, fold `{mediumSpectralHash, mediumOpticsHash}` in that order via `hash_pack`. Avoid inventing new hash families: per-medium spectral + optics hashes plus one per-frame geometry key cover every cache in this plan.
    - Implement `hash_float_span()` and `hash_pack()` once in `HashUtils.h` using 64-bit FNV-1a (NaN→0, -0→0). Every hash listed in this step must call those helpers so cache invalidations follow one code path.
    - `scannerSettingsHash`: `hash_pack(useLut, lutResolution, lensBlurSigmaPx, unsharpSigmaPx, unsharpAmount)`.
    - `SpectralLutBuffer` stores **two** hashes: `cacheKey = hash_pack(buildCounter, mediumSpectralHash, scannerSettingsHash)` (used for cache invalidation and mirrors the deterministic inputs spelled out above) and `contentHash = hash_float_span(cpuSpan)` computed immediately after the LUT buffer is regenerated. The cache key governs rebuild/purge logic, while the content hash fingerprints the actual samples for parity checks or GPU uploads; both ride inside the struct so CPU/GPU paths never fall out of sync and caches naturally retire when `buildCounter` bumps.
    - `frameBoundsVersion` remains the sole geometry key. Store it on `InstanceState` next to the cached clip bounds and bump it whenever `JuicerProcessor::render()` detects that `srcImg->getBounds()` changed. In this step, thread `{frameBoundsVersion, clipBounds}` directly through the existing processor path (e.g., setters on `JuicerProcessor` that feed `renderSpatialDIR`/scalar kernels) so blur caches and RNG seeds already respect the monotonic key. Step 3 will replace the ad-hoc threading with the stage context, but the raw data is available immediately.
  - Delete the Film-Juicer-only scanner controls (`ScannerEnabled`, `ScannerAutoExposure`, `ScannerTargetY`, `ScannerFilmLongEdgeMm`) and replace them with the four values required for agx parity: `ScannerLensBlurSigmaPx`, `ScannerUnsharpMask`, `ScannerUseLUT`, and `ScannerLutResolution`. The first two mirror `params.scanner.lens_blur`/`unsharp_mask`, and the latter pair explicitly governs `_spectral_lut_compute` so GPU/CPU paths share one switchboard. All four controls ship together so Resolve presents a stable surface from the first refactor drop. Blur/unsharp sliders feed `Scanner::Options`, and the LUT toggles live inside `Scanner::Settings`, keeping struct ownership fixed before we start moving optics code. No migration path for old presets is required, the new IDs replace the legacy ones outright, and the scanner is always active just like agx (hosts that want a pass-through simply bypass the plug-in).
  - **Scanner parameter reference**
    - `ScannerLensBlurSigmaPx`: `Scanner::Options`, OFX `Double` (`kOfxParamDoubleTypePlain`), hard range `[0.0, 10.0]`, display range `[0.0, 3.0]`, default `0.55`, grouped under “Scanner Optics”.
    - `ScannerUnsharpMask` (`sigma_px`, `amount`): `Scanner::Options`, OFX `Double2D`, sigma range `[0.0, 5.0]`, amount range `[0.0, 3.0]`, default `(0.7, 1.0)`, also inside “Scanner Optics”.
    - `ScannerUseLUT`: `Scanner::Settings`, OFX `Boolean`, default **enabled**, located in the “Scanner Math” expert group.
    - `ScannerLutResolution`: `Scanner::Settings`, OFX `Integer`, range `[17, 128]`, default `17`, hosted alongside `ScannerUseLUT` within “Scanner Math”.
  - Extend `ProfileJSONLoader` with the exact profile-backed slices consumed by agx during scanning: `negative.grain.active`, `negative.grain.density_min`, and the full `glare` objects for both `negative` (active/percent/roughness/blur) and `print_paper` (active/percent/roughness/blur plus `compensation_removal_{factor,density,transition}`). Keep these values owned by the profile/base state (they are not scanner sliders in agx) and assert that every ingested profile supplies finite samples before exposing the data downstream. agx never falls back to synthesized glare defaults—it simply refuses to load a profile that omits the block—so Film-Juicer must do the same: treat a missing `glare` object as a fatal profile error instead of silently patching in numbers. Ingest `density_min` in the same CMY ordering agx uses, store it verbatim, and only map into the legacy RGB-layer helpers at the handful of call sites that still expect `densB/densG/densR`; the refactor will eventually delete those remaps once the helpers speak CMY natively. When print glare compensation removal parameters are greater than zero, mutate the print density curves during working-state rebuild exactly the way `remove_viewing_glare_comp()` does (mirroring agx’s `_apply_profiles_changes`) before any render work begins so the scanner never sees compensated data. `InstanceState` caches the promoted JSON `DoublePairs` directly (cyan/magenta/yellow arrays) so every `WorkingState` rebuild can clone the pristine data, optionally run removal, and then linearize into `Spectral::Curve`; `Print::load_profile_from_dir()` continues to return the immutable snapshot so concurrent working states never double-remove glare. Step 2’s density-range capture must point at this cloned, post-removal buffer so there is a single mutation site (`JSON → Print::Profile (immutable) → WorkingState copy → optional removal`) identical to agx’s `_apply_profiles_changes()` ordering.
  - Introduce typed structs that mirror agx’s DotMaps instead of the grab-bag `Scanner::Params`: e.g. `Scanner::Options { float lensBlurSigmaPx; float unsharpSigmaPx; float unsharpAmount; }` (defined in `Scanner.h` next to the optics code) plus `ProfileGlare`/`GrainMetadata` structs carried by `BaseState`/`WorkingState`. `GrainMetadata` only needs the fields required for scanner normalization today (`active`, `density_min` in CMY), but keep the struct in shared state so future grain refactors can append fields without ABI churn. Print glare metadata should live alongside the rest of the paper profile (`Print::Profile`/`Print::Runtime`) so working-state rebuilds can copy both mediums’ glare structs wholesale. Populate the scanner struct exclusively from the runtime parameter block—no more host toggles—and rely on code review/parity docs instead of `static_assert` size guards to keep the surface in sync with agx (the struct is simple enough that assertions add little value).
  - Thread the new structs through `JuicerEffect` → `JuicerProcessor` → scanner runtime using the same field names as agx JSON (`lens_blur`, `unsharp_mask`). `JuicerEffect` fetches the new OFX params, `ParamSnapshot` stores them (but keeps them out of `hash_params()` to avoid rebuild churn), and `JuicerProcessor` hands a `Scanner::Options` to the optics module every render. Wire `WorkingState` rebuilds so the film and print paths pull glare/grain data from the profile objects instead of the host. When print glare removal fires inside the working-state build, reuse the existing `remove_glare_compensation_from_curves()` helper (it already mirrors agx’s `remove_viewing_glare_comp()` math) instead of re-porting it; keep the raw JSON curves intact in `InstanceState` so every build starts from the same baseline while paying the per-build copy cost only when the compensation parameters are active. This mirrors agx’s `_apply_profiles_changes()` lifecycle (immutable profile -> per-render clone -> optional curve mutation), avoids double-removing glare if multiple working states exist simultaneously, and makes it trivial to prove the scanner path always starts from the same on-disk data. The trade-off is a small per-build memcpy/filter cost, but we avoid the more serious drift that would happen if `InstanceState` mutated its cached curves in-place.
  - Treat `negative.grain` and both `glare` blocks as required JSON schema. The shipping `_uc`/`_auc` assets we rely on already ship this metadata (parity with agx-emulsion), so `ProfileJSONLoader` should log a fatal `JTRACE` and abort when those objects are missing or contain non-finite samples instead of synthesizing defaults. This keeps Film-Juicer aligned with the Python reference and surfaces broken custom assets immediately; the trade-off is that legacy community profiles without the metadata will now fail to load, but that is the same contract agx enforces.
  - Store `ProfileGlare`/`GrainMetadata` inside `Profiles::AgxFilmProfile` → `BaseState`, clone them into every `WorkingState`, and keep the print-paper copy inside `Print::Profile`/`Print::Runtime` so the render thread only touches immutable snapshots. The struct layout should mirror agx’s DotMaps (CMY ordering, booleans, compensation fields) so future grain/glare work can drop directly into place; the cost is a bit more plumbing through the loader and rebuild path, but it eliminates ambiguity about ownership.
- **Implementation notes**
  - *Scanner slider churn*: The new `ScannerLensBlurSigmaPx` and `ScannerUnsharpMask` controls only influence runtime convolution, so they should *not* contribute to `ParamSnapshot::hash_params()` or trigger full `WorkingState` rebuilds. Fetch them in `JuicerEffect`, thread them through `JuicerProcessor`, and let the processor rebuild its blur kernels when the values change. That keeps renders responsive, avoids unnecessary rebuilds, and matches agx where `params.scanner` is a per-render DotMap instead of a profile-level knob. The trade-off is that any future scanner logic that *does* rely on rebuilt spectral data must hook into a separate dirty bit, but today’s optics-only sliders don’t warrant the rebuild penalty.
  - *Print glare removal site*: Glare compensation should be stripped inside `rebuild_working_state()` so concurrent working states never double-apply the removal. The helper already lives in `Print.cpp`, so the only work is to retain the JSON curves long enough for the rebuild to call it. Pros: mirrors agx’s `_apply_profiles_changes()`, guarantees per-build determinism. Cons: adds an extra copy step, but the copy happens off the render thread and only on parameter changes.
  - *Ownership & mutation contract*: The data flow must remain `JSON on disk → ProfileJSONLoader → BaseState/Print::Profile (immutable snapshots) → WorkingState clone → optional glare-compensation removal → density-range derivation → render-time read-only access`. Neither `ProfileJSONLoader` nor `Print::Profile`/`Print::Runtime` may mutate the promoted curves after ingest; all compensation and `ScannerDensityRange` derivation happens exactly once per working-state rebuild using the freshly cloned buffers. This single mutation point prevents double-application and keeps scanner metadata (max densities, glare flags, hashes) tied to the post-removal data the render thread consumes.
- **Risks & Mitigation**
- **Risks & Mitigation**
  - *Risk*: Leaving any of the legacy scanner toggles in place lets downstream code double-apply exposure or geometry fixes.  
    *Mitigation*: Remove the parameters outright and gate all scanner runtime construction behind the new struct; parity docs/code review keep the struct surface in sync with agx since the field list is tiny and easy to audit.
  - *Risk*: Profiles without glare metadata would leave the scanner path without `profile.glare.*`, causing crashes or mismatched brightness.  
    *Mitigation*: Do exactly what agx does—treat the profile as invalid. If `glare` is missing (e.g. the `_oc` research variants), abort the ingest and surface a `JTRACE` pointing back to the JSON so the asset gets fixed instead of silently fabricating defaults.

### Step 2 – Rebuild `WorkingState` scanner metadata per medium (negative & print)
- **Implementation notes**
  - Step 1’s structs and JSON ingestion (grain/glare metadata, `ScannerDensityRange`, `ScannerMediumRuntime`, `hash_float_span`/`hash_pack`) must be merged before taking this step so density maxima, glare blocks, and hashes have real data behind them.
  - Phase this work across at least three deltas: (1) viewing-illuminant cleanup + `ScannerIlluminant` struct (delete the UI override, enforce profile names, add the struct + immutable span accessors); (2) spectral-table/cache integration (expose the tables through helpers, make the legacy scanner path consume the new structs); (3) density-range capture + per-medium validity flags (post-glare-removal measurement, flag plumbing, fatal error surfaces). Each chunk stands on its own and keeps regressions localized.
- **Tasks**
  - Build `ScannerIlluminant` records directly from each medium’s `profile.info.viewing_illuminant`, using the same `np.sum(SPD * ȳ)` scalar agx computes before dividing XYZ. Replace the old UI-driven `Print::build_illuminant_from_choice` calls with `build_illuminant_from_string(S.dataDir, profile.info.viewing_illuminant)` so both mediums always consume the profile-authored SPD. The curated CSVs in `Resources/illuminants/` already match the agx axis, so reuse the existing `Spectral::build_curve_*_pinned()` helpers, assert only that `curve.linear.size() == Spectral::gShape.K`, and skip the heavier `json_wavelengths_match_reference_axis()` / `install_standard_illuminant()` plumbing. On failure, log a `JTRACE("SCANNER", …)` entry, set the owning medium’s validity bit to false, and continue rebuilding the other medium so negative-only renders remain functional. `ScannerIlluminant` stores the pinned `Spectral::Curve`, `float normalization` (`∑SPD·ȳ`), `float whiteXYZ[3]`, and `float whiteXY[2]`; it never carries its own hash because Step 1’s aggregate digests consume the samples directly via `hash_float_span()`.
  - Fold in the viewing-illuminant refactor completely: delete the legacy UI overrides (the `ViewingIlluminant` choice parameter, `InstanceState::filmViewingIlluminant`, host parameter fetches, and any downstream checks) so every scanner or print consumer only reads `WorkingState::negativeScannerIlluminant`/`printScannerIlluminant`. Resolve presets need no migration—the parameter simply disappears—and `JuicerEffect`/`JuicerProcessor` no longer track “viewing” overrides at runtime.
  - Cache the full scanner illuminant curve (`Spectral::Curve`), its normalization scalar, and whitepoints, then expose immutable CMY spans from `Spectral::SpectralTables` via helpers such as `tables.cmy_channel(ScannerChannel::Cyan)` that return `{const float* data, int samples}` so downstream code can fold the floats into `mediumSpectralHash` or hand them to the eventual GPU uploads without guessing the struct layout. No `tablesHash` field is needed—the tables change only when the working-state rebuilds, and the aggregated `mediumSpectralHash` already incorporates the channel samples. Glare randomness continues to follow the profile’s `ProfileGlare` struct (added in Step 1) so `mediumOpticsHash` reflects those updates automatically. Provide a thin compatibility shim so the legacy negative-only scanner path (`Scanner::simulate_scanner`) reads from the negative runtime immediately; delete that shim once Stage 3 owns the entry point.
  - Compute `ScannerDensityRange` structs for both media using agx’s per-channel formulas and the CMY fog data ingested during Step 1 (`GrainMetadata::density_min`). Negatives must add `grain.density_min` fog before storing the CMY maxima (`np.nanmax(negative.density_curves, axis=0) + density_min`), while prints use only `np.nanmax(print.data.density_curves, axis=0)` because `_normalize_print_density` never adds a baseline. Perform this measurement inside `rebuild_working_state()` immediately after cloning the already-built `Spectral::Curve` objects (one clone per rebuild; there is no separate JSON `DoublePairs` cache) and, if needed, running `remove_glare_compensation_from_curves()` on that clone. Stash the CMY vectors inside the medium’s `ScannerMediumRuntime` record so Step 1 and Step 2 share the same mutation order (JSON → Profile → WorkingState clone → optional removal → max capture). Skip tolerance diffing; the raw CMY maxima feed directly into `ScannerMediumRuntime.mediumSpectralHash`, so any change naturally invalidates downstream caches.
  - Store explicit per-medium booleans (`negativeScannerValid`, `printScannerValid`) indicating whether each medium’s metadata finished rebuilding. When `PrintBypass=true` (agx’s `compute_negative` path) the engine only requires the negative metadata, so print failures are surfaced via logs/flags but do not prevent the bypass render; conversely, print-mode renders refuse to start unless the print runtime is fully valid and will emit a fatal `JTRACE("SCANNER", …)` that explains which component failed (illuminant, density range, glare metadata, etc.). There is no need for per-subsystem flags (`printGlareCompensated`, etc.); one bit per medium keeps the render path straightforward while still making failure scope explicit.
  - Materialise exactly two `ScannerMediumRuntime` structs inside every `WorkingState` (one tagged `ScannerMedium::Negative`, one `ScannerMedium::Print`). Each runtime bundles `{ScannerMedium mediumTag; ScannerDensityRange range; ProfileGlare glare; ScannerIlluminant illuminant; GrainMetadata grain; const Spectral::SpectralTables* tables; const ColorRuntime* color; uint64_t mediumSpectralHash; uint64_t mediumOpticsHash; bool valid;}` and is populated during rebuild immediately after the density-range measurement. Step 3 consumes these structs verbatim; until then, `Scanner::simulate_scanner` reads the negative runtime through a compatibility helper that asserts `negativeScannerValid` and falls back to today’s behaviour only when the struct is missing (development guard). This keeps cache keys, glare metadata, illuminants, and density ranges in one location and eliminates the pointer guessing that caused the previous regressions.
- **Risks & Mitigation**
  - *Hash churn vs. build counter*: `WorkingState::buildCounter + medium` already invalidates every derived artifact when parameters change. Illuminant/density/glare hashes exist purely to avoid rebuilding LUTs when unrelated parts of the working state toggle; only update them when the source data changes bit-for-bit so caches stay meaningful.
  - *Risk*: Using mismatched illuminants recreates the desaturation bug.  
    *Mitigation*: Assert during working-state rebuild that both scanner tables consume the same SPD hash used for adaptation, and abort the render if a mismatch is detected.
  - *Risk*: Density ranges drifting from agx cause exposure shifts.  
    *Mitigation*: Mirror the exact `_normalize_film_density` / `_normalize_print_density` formulas from `agx_emulsion/model/process.py` and emit a detailed error whenever the cached min/max diverge from `np.nanmax(curves)+grain.density_min` (negative) or `np.nanmax(curves)` (print).

### Step 3 – Refactor the scanner to `ScannerMediumRuntime` while densities stay AoS
- **Implementation notes**
  - Land this as two tightly-scoped drops: (1) delete the compatibility shim from Step 2, thread `ScannerMediumRuntime` through `Scanner::simulate_scanner`, and remove the remaining legacy toggles/param lookups while the optics math still consumes AoS CMY triples; (2) introduce cache plumbing (`ScannerRenderContext`, `ScannerOptics::Runtime`, LUT validation hooks) that consumes the runtime metadata without touching the yet-to-exist density staging buffers. Both changes must prove parity on bypass + print renders before merging so Stage 4 starts from a trusted baseline.
  - Optics stay CPU-only and retain today’s loops over AoS densities. This step is purely about data ownership: per-medium hashes (`mediumSpectralHash`, `mediumOpticsHash`), glare metadata, illuminants, and density ranges become the only inputs the scanner uses, while clip bounds, lens/unsharp toggles, and output encoding stick to the existing codepaths.
- **Tasks**
  - Replace the temporary shim with a real runtime lookup: `Scanner::simulate_scanner` now fetches `{negative, print}` runtimes from `WorkingState`, asserts their validity, and picks `ScannerMedium::Negative` whenever `PrintBypass=true`. Print renders refuse to start until both runtimes are valid, matching Step 2’s failure policy. The per-medium `ScannerDensityRange`, glare metadata, illuminant curve, CAT02 placeholders, and hashes ride through the new `ScannerRenderContext`.
  - Introduce `ScannerRenderContext` and `ScannerOptics::Runtime` structs even though densities remain AoS. The context owns `{AoS density reader, AoS destination PlaneView, ScannerMediumRuntime*, Scanner::Options, OutputEncoding::Params, frame bounds tokens, abort handle}` plus a geometry/lens runtime pointer, and is rebuilt every render. The runtime caches the in-flight LUT buffer, `{lastMediumSpectralHash, lastMediumOpticsHash, lastGeometryHash}`, and a CPU-only flag; Step 4 later extends it with SoA density views while the GPU hooks are deferred to the future backend refactor.
  - Collapse every cache key and RNG seed to `{workingState.buildCounter, ScannerMediumRuntime.mediumSpectralHash, ScannerMediumRuntime.mediumOpticsHash, geometryHash}` so the scanner never hashes UI parameters or illuminants manually again. LUT rebuilds now depend only on the medium’s hashes, while glare kernels depend on `mediumOpticsHash`. Remove the legacy `gScannerOptionsHash` and friends.
  - Wire the negative+print glare metadata through the existing optics helpers, replace the hard-coded viewing illuminant fetches with the runtime’s `ScannerIlluminant`, and make `_normalize_*` helpers pull min/max from `ScannerDensityRange`. Even though the densities are AoS, every normalization and glare branch must already match agx to keep the parity harness meaningful.
- **Risks & Mitigation**
  - *Risk*: Forgetting to delete the compatibility shim leaves dead code that bypasses the runtime.  
    *Mitigation*: Add `JUICER_ASSERT` guards that the runtime pointers are never null and remove the legacy structs entirely in the same change.
  - *Risk*: Rehashing AoS densities per frame regresses performance.  
    *Mitigation*: Keep the existing AoS buffers and only touch hash inputs already computed by the working state; cache keys fold build counters and hashes, not per-pixel data.
  - *Risk*: LUT validation still depends on the density staging layer.  
    *Mitigation*: Bolt the agx parity harness onto the AoS path now (CPU-only) so Stage 4 can focus solely on SoA migration.

### Step 4 – Introduce a shared density staging layer (the missing bridge)
**Plan of attack (ship as incremental milestones)**
  1. **Stage 1 buffers + negative density writer**: introduce lightweight `DensityBuffer` wrappers (three `std::vector<float>` planes + bounds/stride metadata) for each medium, port the existing RGB→density logic (scalar + spatial DIR) into a full-frame pass that fills the negative planes, and keep the legacy print/scanner code paths consuming temporary AoS triples for now.
  2. **Print bridge refactor**: introduce a `PrintBridgeFrameCache` that is populated once per render whenever `PrintBypass=false` (neutral-filtered illuminant, exposure/mid-gray scalar, raw preflash triplet, glare/preflash spectra) and split `run_print_pipeline_from_dir_corrected_densities` into `negative_density_to_print_raw()` + `print_raw_to_density()` helpers that only consume the cache and per-pixel densities. The second full-frame pass writes the print planes using those helpers, matching agx’s “constants once, densities per pixel” cadence while the scanner still reads from the legacy path. The end state keeps both tensors cached in SoA form and readies the code for GPU kernels where the cache becomes uniform data.
  3. **Scanner handoff & optics entry**: alias the `DensityBuffer` wrappers as `ScannerDensityBuffer`, thread them plus `Scanner::Options` into Step 5’s `ScannerOptics::render_density_to_rgb()` entry point, and delete the legacy “RGB→density inside scanner” branch so Stage 3 exclusively consumes the cached tensors. Once this is stable, Step 5 can move scanner optics into their dedicated TU.
  4. **Document the GPU follow-up contract**: Stage 1/2/3 remain CPU-only, and this step ships the staged density pipeline plus parity harness. Capture—in comments and the plan appendix—the entry criteria for the future GPU branch (Steps 1‑6 merged, optics TU split, parity fixtures green) and the high-level APIs it will introduce (`ScannerBackend`, device slab pools, queue abstractions) without adding those hooks to the code yet.
**Tasks**
  - Split the renderer into: (1) RGB → negative densities with DIR + grain; (2) optional print simulation producing print densities; (3) scanner consumption. Resolve reports `supportsTiles=false`, so every `renderWindow` equals the clip bounds; each stage still expands its reads by the maximum halo (DIR diffusion radius, lens blur kernel, glare blur extent) to cover its convolution footprint, but writes remain clamped to the Resolve-provided bounds. Pixels outside the halo are never touched because the host never asks for partial windows. Every halo is now spelled out: `dirHalo = ceil(min(75, 3 * dirRT.spatialSigmaPixels))` (mirrors `buildGaussianKernel`), `grainHalo = ceil(4 * grain.blurSigmaPx)` whenever agx’s grain blur is enabled, `lensHalo = ceil(4 * scannerOptions.lensBlurSigmaPx)`, `unsharpHalo = ceil(4 * scannerOptions.unsharpSigmaPx)`, and `glareHalo = ceil(4 * profile.glare.blurPx)`. Stage 1 uses `max(dirHalo, grainHalo)` to inflate `paddedBounds`, Stage 2 has zero halo, and Stage 3 uses `max(lensHalo, unsharpHalo, glareHalo)`. Halos are clamped so they never exceed the distance to `srcImg->getBounds()`; a fatal `JTRACE("HOST", …)` fires if Resolve fails to provide enough border pixels.
  - Canonicalize the slab layout with `struct DensityBuffer { OfxRectI clipBounds; OfxRectI paddedBounds; int width; int stride; std::array<std::vector<float>,3> planes; uint64_t slabHash; }`. `clipBounds` equals the Resolve window, `paddedBounds` inflates by the halo math above, `width = clipBounds.x2 - clipBounds.x1`, `stride = paddedBounds.x2 - paddedBounds.x1`, and every plane stores CMY data with identical strides so SoA uploads/LUT sampling stay trivial. `slabHash` is only required for diagnostics: under `JUICER_DEBUG_SCANNER` or `JUICER_TESTS` compute the full `hash_pack(frameBoundsVersion, paddedBounds.x1, paddedBounds.y1, paddedBounds.x2, paddedBounds.y2, hash_float_span(planes[0]), …)` to prove CPU/GPU parity, while release builds either skip the per-plane hashes entirely or fall back to a cheap checksum (e.g. XOR of four equidistant stripes). Stage 1/2 only write the clip region, Stage 3 clamps reads to `paddedBounds`, and halos become explicit metadata instead of implicit math in each kernel.
