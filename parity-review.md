# Parity Review – Exposure & Balance

## Task 1 – Provide a fallback when spectral reconstruction tables are unavailable
- **Problem**: `Spectral::rgb_input_to_film_raw` zeros out the layer exposures whenever `ws.spdReady` is false (ColorTransforms.h:442-506). There is no alternative path, so any profile that fails to build the reference S-matrix (missing illuminant, corrupted LUT, custom stock) produces black negatives and the mid-grey normalization collapses to 1. agx-emulsion never drops to zero; it switches between the Hanatos LUT and the Mallett 2019 basis (`external/agx-emulsion/agx_emulsion/model/process.py:282-294`), so the simulation still runs even when the LUT is unavailable.
- **Why it matters**: Exposure and balance debugging becomes impossible whenever the reference illuminant assets are incomplete (a common state while iterating on new stocks). The OFX build also cannot respect the user-facing `Spectral upsampling` parameter (`kParamSpectralMode`) because there is no non-LUT path to fall back to.
- **Suggested fix**: When the LUT/S-matrix path is unavailable, defer to a matrix/basis reconstruction instead of zeroing the exposures. Reuse `rgbDWG_to_layerExposures` or port the Mallett basis so the renderer always has a non-zero exposure, and wire that choice to the existing `SpectralUpsampling` parameter.

## Task 2 – Support ProPhoto RGB as an input color space
- **Problem**: The input space enum only exposes DWG, Rec.2020, and ACES2065-1 (ColorTransforms.h:34-48), and the UI mirrors that list (main.cpp:250-258). agx’s default pipeline operates on linear ProPhoto (`external/agx-emulsion/agx_emulsion/model/process.py:63-67`), so Film-Juicer cannot ingest the same data without pre-converting upstream.
- **Why it matters**: Auto exposure, SPD reconstruction, and the print mid-grey probe all depend on the RGB→XYZ matrix. Using DWG instead of ProPhoto shifts both luminance and chromaticity before the simulation even begins, so matching the reference renders requires extra colour-space transforms outside the plug-in.
- **Suggested fix**: Add ProPhoto RGB to `InputColorSpace`, implement its decode/CCTF and RGB→XYZ matrix, expose it in the UI (ideally as the default), and make sure `apply_input_cctf_decoding` handles its transfer function. This restores parity with agx-emulsion’s out-of-the-box settings and keeps the exposure math consistent.

## Task 3 – Decouple DIR spatial diffusion from the scanner film-size control
- **Problem**: When converting the DIR coupler diffusion from micrometres to pixels (`Couplers::spatial_sigma_pixels_from_micrometers`) the plug-in uses `scannerParams.filmLongEdgeMm` as the physical size reference (JuicerEffect.cpp:456-599). In agx-emulsion the conversion uses the camera film format (`camera.film_format_mm`) and the current render dimensions (`process.py:183-191`, `emulsion.py:235-249`). The scanner long-edge parameter in Film-Juicer therefore changes both the simulated chemistry and the scanning geometry, which is not how the reference behaves.
- **Why it matters**: Users often tweak the scanner long-edge slider to match a target output size. In the current implementation that also changes the coupler diffusion radius, so the same shot will balance differently depending on how you plan to scan it. Exposure compensation masks, halation, and grain will never line up with the Python renders if the diffusion kernel rides on a scanner-only control.
- **Suggested fix**: Introduce a camera film-format parameter (default 35 mm like agx) and base all micrometre→pixel conversions (DIR diffusion, halation, lens blur, grain once implemented) on that value plus the actual render dimensions. Keep the scanner film-long-edge knob scoped to the scanner auto-gain/scale so the chemistry stays constant while the output format varies.
