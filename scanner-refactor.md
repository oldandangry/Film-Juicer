## Scanner Parity Refactor Plan

The goal is to make Film-Juicer’s scanner path numerically identical to **agx-emulsion** while removing all legacy behaviour. The steps below are intentionally self-contained so each can be verified independently. New identifiers mirror the Python names (camelCase → PascalCase/C++ snake case where appropriate) to make A/B reviews trivial.

### 1. Mirror AgX parameter surface and data flow *(✅ complete — new Scanner params, UI wiring, and profile ingestion merged)* 
- **Remove legacy toggles**: Delete the current `Scanner::Params` members (`enabled`, `autoExposure`, `targetY`, `filmLongEdgeMm`) and any UI plumbing that no longer exists in agx. Keep only the controls that agx exposes (`lens_blur`, `unsharp_mask`, glare controls). `ScannerFilmLongEdgeMm` is already unused at runtime but still surfaced in the UI; drop it entirely so the scanner surface matches the Python reference.
- **Delegate geometry to the existing camera control**: Preserve the `CameraFilmFormatMm` parameter defined in `main.cpp:232-240` and thread it through any scanner/glare/lens blur conversions, reusing the same math already applied in `Couplers::spatial_sigma_pixels_from_micrometers`. This ensures every µm→px conversion tracks agx’s `params.camera.film_format_mm` (plus the actual render dimensions) instead of reviving a scanner-only knob.
- **Introduce DotMap-equivalent structs**: Add `Scanner::LensBlurParams`, `Scanner::UnsharpMaskParams`, and `Scanner::GlareParams` mirroring `params.scanner` and `profile.glare` fields in `agx_emulsion/model/process.py:30-89` & `process.py:425-439`. Extend the profile loader to ingest `negative.grain.density_min`, `negative.grain.active`, and `profile.glare` blocks so the new structs have real data to consume.
- **Wire params through JuicerEffect**: Fetch the new parameters in `JuicerEffect`/`main.cpp` using the same names as agx (e.g., `ScannerLensBlur`, `ScannerUnsharpSigma`, `ScannerUnsharpAmount`, glare sliders or presets). Add a boolean UI toggle `ScannerUseLUT` that defaults to **enabled** and exposes a companion integer `ScannerLutResolution` (default 32) so we can opt into denser grids while still matching agx’s behaviour when users choose smaller values. Pass all scanner settings through `JuicerProcessor::setScannerParams` so the render path has the same data that agx’s `photo_params` exposes.

### 2. Rebuild WorkingState scanner assets exactly like agx *(🔄 in progress — caches landed, runtime still needs to consume them)*
- **Scanner illuminant selection** *(✅)*: `WorkingState` now owns `negativeScannerIlluminant`/`printScannerIlluminant` structs populated straight from each medium’s `profile.info.viewing_illuminant`. The build step loads the requested SPD (falls back to D50 if missing), caches the source key, normalization scalar, white XYZ/xy, and keeps the negative illuminant driving the legacy `tablesScan` so renders stay functional until the new medium-aware scanner entry point lands. The UI “Viewing Illuminant” override has been removed; `tablesView`, `tablesPrint`, scanner LUTs, and glare metadata all consume the same profile-derived SPD, mirroring agx’s behaviour.
- **Standard observer tables** *(✅)*: The illuminant helpers reuse the global 2° CMFs already pinned in `SpectralContext`, ensuring the normalization `∑ scanIlluminant * ybar` and cached white points match agx’s math without duplicating CMF storage.
- **Density normalization metadata** *(✅ for data plumbing)*: `WorkingState` now tracks per-medium `ScannerDensityRange` structs built from the negative density curves (with `grain.density_min` fog) and the active print profile’s density curves. These ranges give the upcoming scanner optics module the min/max it needs for `_normalize_{film,print}_density`; the remaining work is to switch the runtime scanner path over to the normalized buffers.

### 3. Reimplement the spectral-to-XYZ stage *(✅ negative path + LUT runtime complete; print medium + density entry still pending)*
- **Spectral LUT parity** *(✅)*: `Scanner::spectral_lut_compute` now mirrors agx’s `_spectral_lut_compute`, rebuilding a per-medium 3D LUT whenever the working state, medium selection, or `ScannerLutResolution` changes. LUT samples are stored as `log10(XYZ + 1e-10)` so toggling `ScannerUseLUT` swaps between the cached grid and the direct spectral integration without numeric drift.
- **`density_cmy_to_rgb` equivalent** *(✅ for negative medium)*: `Scanner::density_cmy_to_rgb` de-normalizes densities using the cached `ScannerDensityRange`, contracts them with the scanner tables, and returns XYZ ready for adaptation. The helper currently feeds the negative path; wiring it to the print medium still depends on the shared density buffer from step 4.
- **XYZ normalization & adaptation** *(✅)*: The scanner path now uses the `WorkingState` scanner illuminant metadata (`normalization`, cached white XYZ/xy) before running `XYZ_to_DWG_linear_adapted`, giving us agx’s normalization constants on every frame.
- **Remaining work**: The runtime still computes negative densities internally and ignores the shared density tensor, so medium switching (negative vs. print) and glare hooks stay blocked until the step‑4 pipeline split lands. Once densities are sourced from the upstream buffers we can reuse `scannerRuntime.printLut` and the existing normalization metadata for the print medium.

### 4. Add scanner optics via a dedicated translation unit
- **New module**: Introduce `ScannerOptics.cpp/.h` (or rename the existing Scanner module) to host scanner-only helpers: density normalization, LUT computation, `density_cmy_to_rgb`, glare injection, and blur/unsharp utilities. Keep `OutputEncoding` as the single place that applies colour-space conversion and CCTF so scanner and print paths stay consistent with the UI.
    - **Glare injection** *(✅ frame-scoped cache landed)*: The PCG32-backed `ScannerRng` now seeds once per frame, and `RenderContext`/`FrameContext` carry the full render window plus absolute pixel indices. `Scanner::GlareCache` keys on frame dimensions, working-state build counters, and seeds so the lognormal glare map is generated/blurred once per frame (negative & print) and reused by every tile—no more seams when OFX hosts split renders. Remaining TODO: keep this cache in sync with the future shared density buffer once step 4’s medium split ships.
    - **Lens blur and unsharp mask**: Implement `ScannerOptics::apply_blur_and_unsharp` identical to `process.py:425-430`, reusing Juicer’s Gaussian and unsharp utilities but preserving agx’s sigma/amount ordering and boundary handling.

- **Single density pipeline**: Split the current monolithic renderer into three explicit stages—(1) RGB → negative densities (with DIR/grain) using the existing logic from `Print::simulate_print_pixel`, (2) optional print development, (3) scan densities to RGB. Store the intermediate density tensor in `JuicerProcessor` scratch (or a shared buffer) so both the print and scanner stages consume the same data, mirroring agx’s `_develop_film` → `_scan` flow.
- **Scanner entry point in both renderers**: Replace `Scanner::simulate_scanner` with `Scanner::render_density_to_rgb`, which consumes the already-developed density tensor (negative or print). When `PrintBypass` is true, call it right after negative development; otherwise call it after print development but before output encoding—parity with agx’s `io.compute_negative`. Wire this new entry point into *both* `renderScalar` and `renderSpatialDIR` so tiled DIR renders do not fall back to the legacy RGB path.
- **Remove redundant conversions**: Delete the “RGB → film raw → density” branch currently inside `Scanner::simulate_scanner`. The scanner now always consumes the density array produced upstream, so there is no duplicate exposure/development path.
- **Ensure medium awareness**: Pass a medium enum so the scanner picks the correct normalization/illuminant pair and so print bypass mirrors agx’s `compute_negative` settings. Sharing the same density buffer will also guarantee that LUT caching and glare normalization stay in sync with whichever medium is active.

### 6. Clean up legacy code and assets
- **Delete obsolete params/functions**: Remove unused scanner auto-exposure code, target-Y UI, and any helpers that only existed for the old bypass path. Update docs (`AGENTS.md`, `agx-documentation.md`, host README/help strings) so they describe the always-on scanner and the `ScannerUseLUT` toggle.
- **Asset verification**: Confirm the repository contains all illuminant CSVs and CMFs agx expects (D50, D55, TH-KG3-L, etc.). If any are missing or normalized differently, regenerate them from agx’s data packages so both projects ingest identical spectra.
- **Testing hooks**: Add JUICER_TESTS probes that run a neutral density patch through the new scanner path and compare XYZ/RGB against agx-emulsion reference values to guard against regressions.

### 7. Validation & parity checks
- Render a controlled chart (step wedge + color checker) through both Film-Juicer and agx with identical settings. Compare:
  - XYZ and RGB after the scanner stage with `ScannerUseLUT` on and off (both paths must match agx’s LUT/direct outputs)
  - Glare noise statistics, using identical seeds
  - Effects of lens blur/unsharp parameters
- Document any residual differences; if asset-related, update the assets; if numeric, tune the math until the results match within float tolerance.

Following these steps ensures the scanner module becomes a faithful transliteration of agx-emulsion, with no lingering legacy paths.

### Recent Fixes
- ✅ Print medium scanner channel swap resolved: print densities stay in C/M/Y for the enlarger math but are reordered to Y/M/C before entering the scanner optics, and the print density normalization cache now matches the scanner’s channel order. This removes the red/blue inversion when `PrintBypass=false`.
- ✅ Viewing illuminant parity: removed the UI viewing selector, single-sourced `tablesPrint`, `tablesView`, and glare/XYZ metadata from `profile.info.viewing_illuminant`, and updated print helpers to read the shared SPD from `WorkingState::printScannerIlluminant`, matching agx-emulsion exactly.
