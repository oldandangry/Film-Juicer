# Prepared-state projection contract

These four independent native captures preserve complete-product composition
before S4E-INTEGRATION removes the native recipe/payload owners. Their authority
is the accepted native composition at the source identities in `manifest.json`.
The current spektrafilm revision is recorded separately; existing scientific
fixtures retain their own authorities and numerical exceptions.

Each preset has all 31 ordered successful products. `expected` is independently
assembled from the native recipe/payload and supplies acceptance values.
`captured_actual` preserves the contemporaneous Rust projection for provenance
and capture-time cross-checking. Ordinary tests compare current Rust output with
`expected`; they never regenerate these files.

Scalars preserve f32/f64 bit words and signed integer widths. Arrays preserve
every word, source field, shape, count and channel order. Recipe, upload, scanner,
print and resource hashes retain their separate lanes. Named backing relations
record actual live pointer-equality assertions; pointer addresses are absent.
Live cache acquisition and retained-owner tests continue proving those relations
and lifetimes at execution time.

The manifest binds each payload's byte count/SHA-256, native target, retained
executable, original supervised preparation result, build/capture logs, toolchain,
configuration and resource identities. Its historical source hashes remain
provenance after the owning producers are deleted. Tests do not read the retained
`out/` records to execute ordinary correctness checks.

Capture used the existing `JuicerPreparedStateTests` explicit
`--capture-state-projection` mode. Each process passed all owning assertions and
exact membership before writing its candidate, followed by the strict parsed-file
`--check-state-projection` mode. The owner explicitly amended the first integer
Boolean case to select NegativeDirectScan, retaining its other controls and all
assertions. The direct/print row IDs describe those actual routes.

Each full payload is about 93 MiB. Complete scientific arrays and original Rust
provenance justify the size above the output review trigger. Debug/Release and
Linux/Windows files remain independent; no context overlay or compaction applies.
