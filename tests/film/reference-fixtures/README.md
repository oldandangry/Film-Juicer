# Synthetic film reference characterization

These are native Film-Juicer migration characterizations, captured before the
synthetic reference producer or either state caller was changed. The complete
native producer composes the previously accepted Rust exposure/color/TC leaves;
these frozen captures did not call the new safe Reference. This is not a Python
pixel reference or installed-host acceptance.

Each logical native configuration owns its payload. The manifest binds the
unchanged producer/caller, baseline Git revision, payload hashes and original
preparation/capture roots. Those roots retain the actual executable, original
capture source, CMake cache/compile commands, before/after executable identities
and drained supervisor receipts. Earlier fixtures and amendments are unchanged.

The 36 rows cover three reconstruction methods, four resolved routes and three
EV/auto combinations. RGB raw and authored-density CMY are three f32 words each;
meter is one f32 word. The reference hash covers exactly those 52 little-endian
bytes in the documented order. Scanner, balance, print, final and payload
identities are exact. Two rows retain the complete borrowed raw inputs for C11,
facade and native-adapter value probes. Nine completed native recipe observations
retain source/raw/meter/subnormal-query failures, missing basis and shape-only
availability behavior, including unchanged local reference/scanner/final values.

Ordinary tests only read these files. Explicit `reference-capture` maintenance
on JuicerFilmRecipeTests writes a fresh candidate under out/validation and never
overwrites an existing capture. `reference-primitives` checks its exact native/
Rust log10 words. Both Windows captures used the separately authorized native
environment before producer replacement. All four payloads are independent
configuration contracts; none may be substituted for another. Capture mode
after cutover observes the replacement and cannot establish new expectations.
